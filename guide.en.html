Install and enable

This plugin connects Matt Pocock methods into resumable workflows and integrates Codex native questions. For suitable use cases, see Two ways to use it; the instructions below target Codex Desktop.

Download Codex plugin · ZIP ↓

  1. Download the ZIP package above.
  2. Drag the ZIP into a Codex Desktop conversation.
  3. Send the following message so Codex can extract and install it.
Copy and send with the ZIP
Please extract and install this plugin, preserving my other plugins and configuration.

After installation, Codex explains both hooks in the current conversation: restoring workflows at task startup and recognizing plugin entry points when you send a message. After you confirm “Trust and enable”, Codex configures them and checks the result. You do not need to find them in settings. If you defer enabling them, the installation remains and you can confirm later in the conversation.

Once ready, start a new task and use @ to select Matt Pocock, then start your first task. Sending only $matt-pocock opens the route menu.

If Codex cannot read the ZIP attachment

Send Codex the ZIP's local path. Alternatively, extract it yourself, open the folder in Codex, and ask it to install according to the README.

Manual installation (fallback)

The following macOS example requires the node and codex command in your terminal. Extract the ZIP, put the entire matt-pocock-codex folder in a location you intend to keep, and preserve the hidden .agents folder.

In your terminal, enter the extracted directory containing the README and run:

Terminal · Run inside the extracted folder
codex plugin marketplace add .
codex plugin add matt-pocock@matt-pocock-team

In Codex, confirm the plugin is enabled and complete trust confirmation for the two SessionStart and UserPromptSubmit hooks before starting a new task. Restart Codex if it still shows the old state.

How do I update an older version?

Download the new ZIP and drag it into Codex. Ask it to save the old plugin package and its matching workflow state before updating, while preserving existing configuration. To roll back, use that matched save point; do not overwrite new records with an older version. Already trusted and enabled hooks do not require another prompt. If trust is required again, confirm in the current conversation and let Codex configure it. If a plugin with the same name comes from another source, ask Codex to check for duplicate installations so only one is enabled.

Open the complete guide at any time

Send only $matt-pocock help, or select the plugin and enter help. The agent opens the local webpage bundled with the installed package. Viewing the guide does not switch or end the current workflow. The preview URL varies with the preview process; this command is the stable entry point.

01 / Start your first task

In the input box, use @ to select the plugin, then describe the task you want to discuss. Here, @ is the host's plugin selector; you do not need to type a plugin tool name in the message.

After selecting the plugin · Example
Add tag filtering to the task list. Discuss behavior first, then write a specification, break down tasks, implement, and review. Reuse existing components; add no dependencies. Save documents in the project, do not publish to external platforms, and do not commit or push code.

For a new feature like this, the usual recommendation is Idea to Ship. After selecting that route, start with requirements discussion; you can also send $matt-pocock idea-to-ship on its own to start explicitly. Add who will use it, whether selection is single or multiple, what happens with no results, and what is out of scope.

The agent asks when a decision needs your input. Entering a workflow does not require an immediate question card and does not mean coding has started.

If you only want discussion this time, add “This round is discussion only; do not write documents or code yet.”. Starting a workflow does not remove your scope limits.

What this step produces

A clear goal, boundaries, and key decisions. Default steps also record context and decision documents as the task requires.

02 / The agent proceeds with the work

Normally, you do not need to enter a command for every step. When the current step's completion conditions are met, the next step is clear, and it remains authorized, the agent should call the workflow tool to switch and begin that step. Common rework within the agreed path can proceed directly. You decide jumps outside that path. Research or prototypes can come first, but skipping a step does not automatically remove its requirements.

For the tag-filtering task above, one possible path follows. This is a usage example, not a record of completed work:

Continuing has conditions

The agent judges whether completion conditions are met. The plugin checks paths, pending questions, and registered requirements, then saves and restores progress. A step transition alone does not prove the feature is correct. Artifacts, tests, and real use still determine the outcome.

03 / You can intervene at any time

Your task scope and explicit instructions take priority. State any narrower scope, additional behavior, or change of direction directly in the conversation:

Limit the scope · Example
Stop at the specification; do not enter implementation. I want multi-tag filtering to use “match any”. Update the specification and acceptance criteria accordingly.

To see the saved workflow's current step, send $matt-pocock status. Standalone capabilities do not start or switch workflows, so inactive does not mean the plugin was unused. To choose a step explicitly, use the manual commands below. They are controls and queries, not a checklist required for every use.

For an unanswered question, return to the original task and say “Continue answering the question”. This restores the original question with its original deadline. See Questions and recovery.

Check before completion

Confirm that requirements are reflected in the actual deliverable, which validations ran, and which issues remain open. Recorded steps do not replace delivery results.

When work is done, the agent records completion based on the current scope, artifacts, and evidence. Sending $matt-pocock end explicitly cancels the current workflow and preserves outstanding requirements; it does not mean completion. A temporary standalone capability call also preserves the original workflow.

Completion, cancellation, and outstanding requirements

For example, if you ask for a prototype first and a specification later, the agent can change the path on your explicit instruction while retaining the pending specification requirement and its source. Close it only when an equivalent result satisfies it or you explicitly cancel it. Changing steps does not remove requirements.

You can ask the agent to “List this round's scope, outstanding requirements, and supporting evidence.” The agent records scope and requirements and cites artifacts and validation results. The plugin checks that these records are complete; it does not decide for you whether the final result is useful.

SituationWhat happens
All registered requirements are resolved and no questions are pendingThe agent checks evidence and records completion with a result summary. Repeating that operation does not end a new task started later.
Requirements or questions remain openKeep the work incomplete and list what remains. Do not clear a question by changing phases and then claim completion.
You decide to stop this roundSend $matt-pocock end to cancel the workflow, preserve outstanding requirements, and avoid marking the result as accepted.
Recover an older recordResume recognizable steps. Do not invent completion when the old record lacks evidence.

If natural language does not establish the source of a route change, the agent asks you to use an existing switch command or menu. You do not need to justify a clear choice again. Switching or ending a phase never expands authorization for external actions.

Five engineering routes and an optional writing route

Idea to ship

idea-to-ship

For new features and multi-step implementation. Start with requirements discussion, then move into research, prototypes, specifications, task breakdown, implementation, review, and handoff as needed. native.24 adds whole-spec implementation and optional retrospectives. See New branches.

Difficult bugs

hard-bug

For hard-to-reproduce, intermittent, or regression issues. Establish feedback that can verify a fix, identify the cause, then implement and review.

Organize requirements

triage

For scattered requests and open issues. Turn them into clear task descriptions, then specify, break down, and implement as needed.

Explore a direction

wayfinding

For large engineering efforts with many unknowns. Identify investigation and decision needs, research or prototype where useful, then create an actionable plan.

Improve architecture

architecture

For modules, interfaces, and code structure. Find improvement opportunities, then choose a module for deeper design, implementation, and review.

Optional writing route

$matt-pocock writing Start by collecting material. If material already exists, ask to enter writing-shape to draft paragraph by paragraph, or writing-beats to choose each narrative beat without repeating the interview.

Each round writes only the paragraph or beat you confirm. Files are reread before writing, your edits are preserved, and source material remains unchanged during drafting. Recovery checks material, article path, and continuation point, asking only for missing information. The route does not publish automatically; you judge each passage and the actual result.

Question cards and recovery

When does the agent ask a question?

The agent asks when a scope, cost, compatibility, or experience tradeoff needs your decision. Settled choices, independently verifiable facts, and authorized implementation should proceed directly. No card does not imply a capability was not executed.

If the host cannot collect a required product decision through a card, the agent explains the limitation and discusses it in the conversation. If a related card is already pending, you must explicitly cancel that old question before the agent can proceed with the conversational decision. Ordinary chat is not recorded as an answer to the original card, and cancellation does not make a business choice for you.

How can I tell what is happening without a card?

Say “Please check the workflow and question status for the current Matt task”. The agent queries unified status: the saved route and step, unanswered questions and their presentation mode, and recent question records. The query neither displays nor restores a card.

Standalone capability execution has no persistent progress record. Loaded content does not prove execution, and an inactive workflow does not prove a capability was unused. A prepared question does not prove you saw its card; no pending question does not prove business completion. Check artifacts and validation evidence for actual completion.

How do I choose synchronous or asynchronous cards?

Synchronous mode is preferred by default. Ask the installation assistant to set the plugin MCP server environment variable MATT_POCOCK_CARD_MODE to sync or async. New questions also support an explicit presentation override. Changes affect only new questions; pending questions keep their original mode.

Synchronous use remains subject to the current Codex mode and does not guarantee indefinite waiting. New synchronous questions have no business deadline by default; empty answers to required questions do not advance. Larger option sets require paging. native.16 checks compatibility using the session, history prefix, original question, and actual answer evidence, rather than a product version allowlist. Unknown protocols keep the question pending and explain why. Plugin answer adaptation and host card display are separate concerns; whether an asynchronous card remains answerable after a turn ends depends on the host.

Will an unanswered optional preference block the task?

You can leave it unanswered. For a clarification declared optional at creation, an empty return or “No additions (optional question)” ends the wait. If the input tool is unavailable, the agent may explicitly end that optional wait. It continues with a default you previously allowed or its judgment within the authorized scope, explains that basis, and never records the default as your answer.

Required decisions, permission confirmations, and menus cannot become optional questions. Ending an optional wait does not automatically close the host card; a late answer to an old card cannot rewrite a completed result. An answer already being committed must recover its result first and cannot be overwritten by cancellation.

What does “Keep pending (default protection)” mean?

It preserves the question without choosing a business answer or advancing the workflow. Select a business option when a decision is needed. Recommendations appear in that option's description.

I clicked Skip, or the turn ended. How do I continue?

Say “Continue answering the question” in the original task. The plugin finds the saved unanswered question. Asynchronous mode presents another card for the same business question, preserving its text and original deadline. This requires an additional recovery message; it does not reopen the old card from a completed turn, and an unsubmitted draft on that card may not carry over. Skip does not mean cancellation, timeout, or approval. Do not rely on an old card remaining directly submittable after its turn ends.

How long can I answer a recovered question?

Recovery and paging do not reset the original deadline. After timeout, late replies are not valid decisions. Explicitly request a new question if needed.

Can I enter my own answer?

If the question allows custom answers, type directly on the same card. Menus and questions without custom answers accept only listed choices; a host text box does not mean every question accepts arbitrary text.

How do I cancel a question or end the workflow?

To cancel the current question, explicitly say “Cancel the current question” in the conversation. To cancel the entire workflow, send $matt-pocock end; outstanding requirements remain. Cancellation is not completion, and these two operations have different scopes.

Why did it not advance automatically?

Check whether the current step is complete, whether questions are pending, and whether you limited the task to discussion or deferred implementation. If the next step is clear and none of these blocks applies, the agent should switch and continue directly. Repeatedly asking whether to continue solely because a phase ended conflicts with current guidance. Ask it to state the specific blocker, and use $matt-pocock status to inspect saved status.

Do I need this plugin if I already have the original Matt skills?

The original skills can combine and guide the agent's ongoing work. This plugin adds unified routes, resumable step state, and Codex question interaction. An original skill can serve a single review or a free combination of methods; choose the plugin when work spans several steps and progress needs ongoing management. See Two ways to use it.

Common problems

The plugin is missing from @, or still shows an old version after updating

Check installation and enabled state in the current environment; installations may differ across machines. Check in a new task and restart Codex if needed. Instructions already loaded in an old task do not establish that the new version is active.

Selecting the plugin and sending did not open the menu

The expected behavior is to open the route menu. Try $matt-pocock again. If it still fails, tell the agent “The route menu did not appear” in the current task and preserve any error message for diagnosis.

Workflow tools are not loaded, or startup times out

Confirm the plugin is enabled and retry in a new task. If it still fails, give the agent the full error. Reading the skill does not mean the workflow has started.

Status or question cards differ from what I expected

Say “Please check the workflow and question status for the current Matt task” to inspect the saved route and pending questions together. For only the route and step, send $matt-pocock status. Restore unanswered questions with “Continue answering the question”. Cancelling a question and ending a workflow are different actions. Do not assume another task inherits the original task's questions and decisions.

The guide closed and my bookmarked URL no longer works

A preview process serves the local page; its URL stops working when that process closes. Send $matt-pocock help again to open the guide from the installed package. If the embedded browser is unavailable, the agent should provide a local file link and answer from its content.

How references follow capabilities

Whether entering a workflow step or using a capability independently, the agent receives its main content and all declared required references, with shared resources loaded once. Optional templates, examples, and attachments are listed for later reading; you do not need to remind it about each file.

Missing references, dependency cycles, or loading-limit violations produce an error while preserving progress. Partial resources are not treated as fully loaded. Scripts in attachments are reference material and do not execute merely because they are read.

code-review checks AI slop such as unsupported type assertions, type widening that loses precision, redundant defenses, mocks replacing internal implementations, and vague names. Findings must reflect project rules and the specific change with evidence. Checks already covered by existing tools do not generate duplicate issues.
