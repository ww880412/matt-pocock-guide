01 / 恢复

上下文里的“进行中”，
已经不是任务的最新状态。

恢复旧会话时，marker 仍指向实现阶段；源实例随后已完成。仅靠那段上下文继续，会把结束的工作重新激活。

旧 marker→源事件核对→保留已结束状态

恢复要追溯事实来源

marker 必须在源会话账本中匹配，并对应相同状态的事件；同一实例的已完成或已取消状态，在恢复时保持终态。

得到的保证已结束实例不会被旧阶段记录重新激活。历史不可信或不可用时，如实保留恢复限制。
查看实现落点

core/restore/index.mjs：可信 marker、源事件匹配、生命周期终态。core/store.mjs：会话事件与锁。

02 / 决定

上一题的迟到答案，
不能成为这一题的选择。

问题 A 被替换后，旧卡片的回答仍可能到达。模型看到一句“同意”，并不能据此替问题 B 完成决定。

A 的答复→问题 / 来源核验→B 继续未决

核验交互证据，再消费答案

Codex 桥接读取可信会话中的原生记录，核对问题关联、提交顺序和有效性；接口拒绝模型传入答案或任意 transcript 路径。

得到的保证旧回答不能被当作新问题的有效答复。无法唯一关联时，不猜测用户选择。
查看实现落点

native/proof.mjs：宿主记录与问题关联。native/server.mjs：bind / collect、只接受回复引用。以上均位于 Codex native 适配目录。

03 / 投递

状态已经写入，
方法正文却没有成功送达。

一次调用完成了状态记录，却在输出阶段中断。下一次触发需要补送正文，同时识别已经发生过的状态变化。

事件已记录→待确认投递→复用事件重发正文

把“任务推进”与“正文送达”分开

claim 标记待投递事件，输出写出后 ack；同一待投递事件可以重发，已识别的调用重试复用原事件。

得到的保证正文补送有明确的事件身份。投递回执只证明对应输出环节，不证明模型已遵循方法，也不承诺外部工具副作用只发生一次。
查看实现落点

core/delivery.mjs：claim / ack / unclaim。runtime/server.mjs：调用来源去重与输出回执。

03 / 架构取舍

控制到哪里，复用到哪里

判断边界

把可检查的规则交给代码

代码校验合法路线、问题是否待答、要求是否未决、资料版本是否匹配。方案是否正确、需求是否充分，保留模型判断与人的验收。

代价与边界插件不能自动担保专业质量；完成证据的内容仍需真实验证。

宿主边界

共享核心，保留适配差异

宿主已有的模型循环、工具和会话直接使用。Hook、MCP 和原生问答按宿主接入；任务规则保持共享，每个安装包自包含。

代价与边界协议和交互仍需分宿主验收，新增宿主版本可能需要更新适配。

抽象边界

先证明重复负担，再抽 SDK

当前机制已经服务 Matt。通用动作契约、决定回执与宿主能力是候选复用职责，仍需第二个真实任务检验，领域状态继续由各任务定义。

代价与边界短期保留内部模块，避免在用途尚未证明前引入共同运行时。
