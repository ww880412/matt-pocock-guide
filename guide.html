安装与启用

本插件把 Matt Pocock 方法串成可恢复的工作流，并接入 Codex 原生问题交互。适用场景见两种用法对比；以下说明面向 Codex Desktop。

下载 Codex 插件 · ZIP ↓

  1. 下载上面的 ZIP 安装包。
  2. 把 ZIP 拖入 Codex Desktop 的对话框。
  3. 发送下面这句话，让 Codex 完成解压和安装。
复制后，与 ZIP 一起发送
请解压并安装这个插件，保留我已有的其他插件和配置。

安装后，Codex 会直接在当前对话说明两个 hooks 的用途：开始任务时恢复工作流、发送消息时识别插件入口。你确认“信任并启用”后，Codex 自动完成设置并检查结果，无需自己去设置里查找。选择暂不启用时保留安装，稍后可在对话中继续确认。

确认就绪后开始新任务，通过 @ 选择 Matt Pocock，或发送 $matt-pocock 打开路线菜单。

如果 Codex 读不到 ZIP 附件

把 ZIP 的本地文件路径发给 Codex；也可以自己解压后，在 Codex 中打开文件夹，再让它按 README 安装。

手动安装（备用）

以下步骤以 macOS 为例，需要终端可用的 node 和 codex 命令。解压 ZIP，将整个 matt-pocock-codex 文件夹放到准备长期保留的位置，并保留隐藏的 .agents 文件夹。

在终端进入包含 README 的解压目录，执行：

终端 · 在解压后的文件夹内执行
codex plugin marketplace add .
codex plugin add matt-pocock@matt-pocock-team

在 Codex 中确认插件已启用，并完成 SessionStart 和 UserPromptSubmit 两个 hooks 的信任确认，再开始新任务；仍显示旧状态时重启 Codex。

已有旧版，如何更新？

下载新版 ZIP，拖入 Codex，让它先保存旧插件包和对应的工作流状态，再更新并保留现有配置。需要回退时使用这组匹配的保存点，不要用旧版覆盖新产生的记录。已信任且启用的 hooks 不重复询问；需要重新信任时，仍在当前对话确认，由 Codex 完成设置。若有其他来源的同名插件，让 Codex 检查重复安装，避免同时启用两份。

随时打开完整指南

单独发送 $matt-pocock help，或选中插件后输入 help。agent 会打开随安装包附带的本地网页；查看指南不会切换或结束当前工作流。网页地址随预览进程变化，固定入口始终是这条命令。

本版变化

native.16 补齐可选问题的结束状态：可选题空答或明确结束可选等待后记录为未补充，不伪造用户选择；必需题空答仍保持待答。提问用途受宿主限制时，采用已约定的普通对话路径；已有未答题须先明确取消成功。兼容性继续按协议与来源证据校验。本版通过组件与限定真实宿主合成场景验证，新增真人交互尚待验收。异步回合结束后仍需发送恢复消息才能重呈现原题。

此前版本将五项增量放进同一套使用方式：能力更容易找到，资料按需跟上，跳步后仍记得欠什么，结束时分清完成和取消。

  • 统一能力目录：保留原34项，新增独立 deslop，共35项。
  • 完整资料加载：必需参考随能力一起读取，可选附件需要时再读。
  • 明确推进路径：正常推进与常见返工可自主进行，你改变路径时保留遗留要求。
  • 完成和取消分开：完成前核对已登记要求与待答问题；取消保留未完成事项。
  • 评审后限定清理：评审增加 AI slop 检查，deslop 在授权范围内修改并验证。
验证范围

五项增量已通过自动化回归、包完整性及指定真实宿主场景验证；写作问答恢复与所选产物、待答守卫和真实指令来源已补验。其他场景及真人体验按风险保留，Claude Code 验证继续后置。

能力目录与独立使用

只想写一份问卷、听一遍简化解释或做一次评审时，可以独立使用能力，同时保留正在进行的工作流。

你想做什么输入
浏览能力、用途和产出$matt-pocock skills
描述任务，获得推荐$matt-pocock skills 帮我编写一份问卷
直接使用选定能力$matt-pocock use to-questionnaire
重新解释当前进展$matt-pocock use wait-what

当前下载包包含35项公开能力。ask-matt 提供流程地图，loop-me 编写业务循环规格，三项 writing 能力承接素材与成文；三个项目工具需在使用时核对配置和依赖授权；新增 deslop 用于限定范围的代码清理。Beta / misc 标识保留上游层级。

推荐会说明理由，等你选择后再执行。独立能力完成后交付结果，不会自动推进原路线；需要追问时仍使用原有问题卡。没有活跃工作流也能使用。

目录只列公开能力，模板和内部参考不会作为入口。本页及下载包面向 Codex；Claude Code 的实际使用验证另行进行。

资料如何跟随能力加载

无论进入工作流步骤还是独立使用能力，agent 都会拿到正文和该能力声明的全部必需参考，共享资料只加载一次。可选模板、示例或附件会提示出来，需要时再读取；你不必逐份提醒。

遇到资料缺失、循环依赖或内容超出加载上限，插件会报错并保留当前进度，不把残缺资料当作已经加载完成。附件中的脚本只作为资料提供，不会因读取而自动执行。

评审与限定范围的代码清理

code-review 会检查缺少依据的类型断言、丢失精确信息的类型放宽、多余防御、替换内部实现的测试 mock，以及空泛命名等 AI slop，结合项目规则和具体变更给出证据；已有工具覆盖的检查不重复制造问题。

要清理评审发现的问题，单独发送 $matt-pocock use deslop，再说明修改范围和目标。例如：

限定清理范围 · 示例
清理本次标签筛选改动中评审确认的多余代码。先列问题和修复意图，再在这次改动范围内修改；保持行为不变，运行相关验证，不新增功能、不提交代码。

agent 先列问题和修复意图，再按已有授权修改、验证和报告。缺少必要行为验证时只给问题清单，不自动重写；验证失败时停止这次清理，保留可恢复状态，不顺手修无关问题。deslop 不会默认插入每条路线，独立调用也不会切换原工作流。

01 / 你提出任务与边界

在输入框通过 @ 选择插件，随后输入你要讨论的任务。这里的 @ 是宿主里的插件选择入口，不需要在消息里手写插件工具名。

选中插件后输入 · 示例
给任务列表增加标签筛选。先讨论行为，再形成规格、拆解任务、实现并评审。复用现有组件，不新增依赖；文档保存在项目内，不发布到外部平台，不提交或推送代码。

这类新功能通常会推荐 Idea to Ship。选择该路线后，从需求讨论开始；也可单独发送 $matt-pocock idea-to-ship 明确启动。你可以补充使用者是谁、单选还是多选、没有结果时如何显示，以及哪些事这次不做。

有必要由你决定的问题时，agent 会发起提问。进入工作流本身不要求立即出现问题卡；也不表示已经开始编写代码。

如果这次只想讨论，直接加上“这轮只讨论，先不要写文档或代码”。开始工作流不会取消你的范围限制。

这一步得到

清楚的目标、边界和关键决定；默认步骤也会按任务需要记录上下文与决策文档。

03 / 你随时可以介入

用户的任务范围和明确指令优先。要缩小范围、补充行为或改变推进方向，直接在对话中说明：

限制推进范围 · 示例
先停在规格这一步，不进入实现。我想把多标签筛选改成“匹配任意一个”，请同步修正规格和验收标准。

想知道保存的工作流处于哪一步，发送 $matt-pocock status。独立能力不会启动或切换工作流，因此 inactive 不表示插件没有被使用。希望明确指定步骤，可以使用下方手动切换命令；它们是干预和查询入口，不是每次使用都必须执行的清单。

对于尚未回答的问题，回到原任务说“继续回答问题”。恢复的是原题，原来的期限仍然有效；详见问答与恢复。

完成时检查

需求是否落进实际产物，哪些验证已做，哪些问题仍未解决。记录的步骤不能替代交付结果。

工作完成时，agent 根据当前范围、产物和证据正式登记完成。主动发送 $matt-pocock end 表示取消当前工作流，保留遗留要求；这不代表已经完成。临时独立调用能力仍保留原工作流。

完成、取消与遗留要求

例如你要求“先做原型，规格稍后补”，agent 可以按你的明确指令改变路径，并保留“规格待补”及其来源。只有等价成果已满足要求，或你明确取消该要求，才能关闭它；换一步不代表少做一项。

你可以让 agent “列出本轮范围、未完成要求和对应证据”。agent 负责登记范围与要求、引用产物及验证结果；插件检查这些记录是否齐备，不代替你判断最终成果是否有用。

情况处理方式
本轮已登记要求全部解决，且没有待答问题agent 核对证据后正式登记完成，保留结果摘要；重复登记不会再次结束后来开始的新任务。
仍有遗留要求或未答问题保持未完成，列出剩余事项；不能先切阶段清掉问题再宣称完成。
你决定停止这轮工作发送 $matt-pocock end 取消工作流，保留遗留要求，不标记为成果通过。
恢复旧版记录承接可识别的步骤；旧记录没有完成证据时，不补成“已完成”。

如果仅凭自然语言无法确认改路来源，agent 会请你使用已有切换命令或菜单，不要求重新论证已明确的选择。切阶段和结束都不会扩大外部操作授权。

可以通过插件入口描述任务，也可以用 $matt-pocock 路线名 明确启动对应路线。

从想法到交付

idea-to-ship

适合新功能和多步骤实现。从需求讨论开始，可根据任务进入研究、原型、规格、拆解、实现、评审和交接。

疑难故障

hard-bug

适合规模大、未知多的工程工作。先识别调查和决策事项，必要时研究或做原型，再制定可执行的方案。

architecture

适合模块、接口和代码结构改进。先寻找改进机会，再选择具体模块深入设计、实现和评审。

可选写作路线

$matt-pocock writing 从素材采集开始。已有素材时，可以直接要求进入 writing-shape 逐段成文，或 writing-beats 逐节点选择走向，不必重新访谈。

每轮只写你确认的段落或节点；写前重读文件，保留你的编辑，成文时不改原始素材。恢复时核对素材、文章路径与接续位置，缺信息再补问。路线不自动发布；每段内容和实际结果仍由你判断。

问题卡与恢复

什么情况下会提问？

有需要你决定的范围、成本、兼容性或体验取舍时，agent 才会提问。已经确定的选择、能自行查证的事实和已授权的实现工作应直接推进；没有卡片本身不表示能力没有执行。

如果宿主不允许用卡片收集某项必需产品决定，agent 会说明限制并在普通对话中讨论。如果已经有相关待答卡片，需要你明确取消该旧题，取消成功后才能按对话中的决定继续。普通聊天不会记作原卡的回答，取消也不会替你作出业务选择。

没出卡，怎样知道现在在做什么？

可以说“请查看 Matt 当前任务的工作流和问题状态”。agent 会查询统一状态：保存的路线与步骤、未答问题及其呈现方式、最近问题的记录。查询不会出卡或恢复问题。

独立能力的执行进度没有持久记录；已加载正文不等于已经执行，工作流 inactive 也不等于能力未被使用。已准备的问题不证明你已经看见卡片；没有未答问题也不证明业务任务完成。实际完成情况仍需核对产物和验证证据。

如何选择同步或异步卡片？

默认优先同步。可让安装助手将插件 MCP server 环境变量 MATT_POCOCK_CARD_MODE 设为 sync 或 async；新题也支持 presentation 显式覆盖。修改只影响新题，已发出的未答题保留原方式。

同步使用仍受 Codex 当前模式限制，不保证无限等待。同步新题默认没有业务期限，必需题空答不推进；选项较多时需要翻页。native.16 按会话、历史前缀、原题和实际答复证据判断兼容性，不再按产品版本号放行。未知协议会保留待答并说明原因。插件答案适配与宿主卡片显示是两个独立问题；异步回合结束后原卡持续可答仍受宿主限制。

可选偏好没有回答，会卡住任务吗？

可以不作答。对于创建时已声明为可选的澄清，空返回或“不补充（可选问题）”会结束等待；输入工具不可用时，agent 也可明确结束这一可选等待。它会按你事先允许的默认方式或已授权范围内的自主判断继续，并说明依据，不把默认值记作你的答案。

必需决定、权限确认和菜单不能改成可选题。可选等待结束不会自动关闭宿主卡片；迟到的旧卡回复不会改写已经完成的结果。正在提交的答案必须先恢复结果，不能被取消覆盖。

“保持待答（默认保护）”是什么意思？

它保留问题，不会选择业务答案，也不会推进工作流。需要做决定时，请主动选择业务选项；推荐意见会出现在对应业务选项的说明中。

我点了 Skip，或者这一轮结束了，怎么继续？

在原来的任务里说“继续回答问题”。插件会查找保存的未答题；异步模式会为同一业务问题重新呈现一张卡，问题和原期限保留。这需要额外发送一次恢复消息，不是直接重开已结束回合的旧卡；原卡未提交的草稿不保证带入新卡。Skip 本身不表示取消、超时或批准，也不要依赖已结束回合的旧卡仍能直接提交。

恢复的问题还能回答多久？

恢复和翻页不会重置原题的期限。如果问题已经超时，迟到的回复不会成为有效决定；需要重新提问时，明确要求发起新问题。

我能输入自己的答案吗？

问题允许自定义回答时，可以直接在同一张卡上输入。菜单或不允许自定义的问题只接受列出的选项；宿主显示自由输入框，不代表所有题目都接受任意文字。

想取消问题，或结束整个工作流？

取消当前问题时，在对话里明确说“取消当前问题”。如果要取消整个工作流，发送 $matt-pocock end，遗留要求会保留。取消不会登记为完成，两个操作的范围不同。

为什么没有自动走到下一步？

先检查当前步骤是否已完成、是否有未答问题，以及你是否限定了“只讨论”或“先不实现”。如果下一步明确且没有这些阻塞，agent 应直接切换并继续；只因阶段结束而反复问“要不要继续”，不符合当前推进指引。可以要求它说明具体阻塞，并用 $matt-pocock status 查看保存的状态。

已经有 Matt 原版 skills，还需要这个插件吗？

原版 skills 也能互相组合、指导 agent 继续工作。插件增加的是统一路线、可恢复的步骤状态和 Codex 问题交互。只做一次评审或自由组合方法时，原版 skill 就可以；跨多个步骤、需要持续管理进度时，可以选择插件。详见两种用法对比。

常见故障

@ 列表中没有插件，或更新后仍是旧版

检查当前环境的安装与启用状态；不同机器的安装不一定同步。开始新任务再查，必要时重启 Codex。不要仅凭旧任务中已经加载的指令判断新版本是否生效。

只选中插件发送，却没有打开菜单

预期是打开路线菜单。可用 $matt-pocock 再试一次；如果仍失败，请在当前任务中说明“没有出现路线菜单”，让 agent 排查，并保留报错信息。

提示工作流工具未加载，或者启动超时

先确认插件已启用，在新任务中重试。仍然失败时，将完整报错交给 agent 排查；不要把“已读取技能”当作工作流已经启动。

状态、问题卡与我预想的不一致

说“请查看 Matt 当前任务的工作流和问题状态”，一起核对保存的路线与待答问题；仅查路线与步骤可发送 $matt-pocock status。未答问题用“继续回答问题”恢复；明确取消与结束工作流是不同操作。更换到另一个任务时，不要假设它自动继承原任务的问题与决定。

指南页面关闭了，收藏的地址打不开

本地网页由预览进程提供，关闭进程后该地址会失效。重新发送 $matt-pocock help 即可从当前安装包打开指南。内置浏览器不可用时，agent 应提供本地文件链接并按内容回答。
